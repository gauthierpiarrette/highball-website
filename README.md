# gethighball.com

The Highball website: landing page, the compatibility database, per-game pages, and the docs.

Static HTML generated by `build.py` from two sources:

- **this repo** — hand-written pages in `content/`, styles and images in `static/`
- **[highball-db](https://github.com/gauthierpiarrette/highball-db)** — the compatibility data (games,
  recipes, reports, anti-cheat data, ProtonDB-derived predictions)

No frameworks, no dependencies, no build toolchain. Python 3.9+ and the standard library.

## Build locally

```sh
git clone https://github.com/gauthierpiarrette/highball-db.git ../highball-db   # once
python3 build.py --db ../highball-db --no-predictions                          # fast: skips the 12k prediction pages
python3 -m http.server -d dist 8000                                            # http://localhost:8000
```

Drop `--no-predictions` for a full build. Flags: `--db`, `--out`, `--base`.

## What gets generated

| URL | Source | Indexed |
|---|---|---|
| `/` | `build.py` (landing) | yes |
| `/database/` | highball-db, filterable | yes |
| `/games/<slug>/` | one page per curated game: renderer matrix, freshness stamp, provenance, notes, recipe | yes |
| `/games/<slug>/` | one page per ProtonDB-derived prediction | **no** (`noindex,follow`, kept out of the sitemap) |
| `/vs/<slug>/` | `content/vs/*.html` — comparisons | yes |
| `/docs/<slug>/` | `content/*.html` — install, troubleshooting, anti-cheat, data, credits, referee pages | yes |
| `/sitemap.xml`, `/robots.txt`, `/CNAME` | generated | — |

Predictions are deliberately excluded from the index and the sitemap: they are derived from Linux data and
carry no Mac-specific evidence, so publishing 12k of them as indexable pages would be thin content. A page
graduates to indexable when it gains a Highball-specific signal (a report, a recipe, or a curated entry).

## Editing content

Pages in `content/` are HTML fragments. The first line is the metadata comment:

```html
<!-- Page title | Meta description, 140-155 characters -->
<h1>…</h1>
```

Available placeholders, filled at build time: `{verified}`, `{curated}`, `{derived}`, `{blocked}`, `{year}`.
Because the files go through `str.format`, literal `{` and `}` are not allowed.

Useful classes: `note`, `note bad`, `note good`, `pill good|info|warn|bad`, `tablewrap`, `btn`, `btn ghost`, `sub`.

## Deployment

Pushes to `main` build and deploy to GitHub Pages via `.github/workflows/deploy.yml`. The workflow also runs
daily and accepts a `repository_dispatch` of type `db-updated`, so a data change can trigger a rebuild:

```sh
gh api repos/gauthierpiarrette/highball-website/dispatches -f event_type=db-updated
```

Before uploading, the workflow asserts that every curated game produced a page and that no `noindex` page
leaked into the sitemap.
